# Design critique — 2026-09-26

**Method:** two independent assessments, each run as a separate sub-agent.
- **A: design review.** 34 Playwright screenshots (desktop and Pixel 7) plus the source.
- **B: Impeccable detector.** `impeccable detect --json src/app src/features src/components`.

No browser overlay was run: the app needs a database to render, so B is a static scan only. The two assessments were combined afterwards.

**Mode:** Operate for the app and admin, Persuade for the landing page. This is a refinement of the existing green identity, not a replacement visual world. The owner's brief says not to redesign working flows for novelty.

## Design specificity

**Mostly template-interchangeable.** The product's character lives in its copy and rules:
- peso fare ranges;
- the CSU-email requirement;
- the no-academic-work banner;
- dialogs that name the person and the consequence.

It doesn't live in its visuals. Hero with a green clause, tinted-icon category tiles, three numbered circles, gradient greeting cards, KPI tiles: any gig marketplace could ship this. The commission lifecycle (open → hired → delivered → reviewed → rated) is the most product-specific thing the app could show, and it has no visual language at all.

**Detector (B): 3 warnings.**
- `side-tab`, `src/app/admin/logs/page.tsx:45`, the coloured `border-l-4` on log rows. **Agrees** with A's point that the logs are a wall of enums.
- `ai-color-palette`, `src/features/profile/profile-card.tsx:10`, a purple-to-pink gradient on a skill-level bar. **True, small scope.**
- `gray-on-color`, `src/features/profile/skills-manager.tsx:72`. **False positive:** it pairs a `hover:` background with the resting text colour. The real problem there, missed by the detector, is slate-400-on-white contrast on an icon-only button.

**Also found:** no web font is loaded. `Inter` is named in CSS but never fetched, so the UI renders in the device default (Segoe UI or Roboto).

## What works
1. **One shared dialog** (native `<dialog>`) for Apply, Accept, Rate, Report and Suspend. The copy names the person and states the consequence.
2. **Domain rules appear where the decision happens:** the academic-integrity banner, the low-rating feedback rule, and the cover-letter counter.
3. **The `Field` form system:** labelled controls, "(optional)" markers, hints, and inline errors that take focus.

## Priority issues

1. **[P1] Two shells, and posted work lives in four places.**
   - `/saved` and `/commission/[id]` use the public header even when you're signed in.
   - Your own posted work is split across My Hub, Commissioner View, My Listings and All Applicants.
   - **Fix:**
     - Signed-in users see these pages inside the app shell.
     - Rename "Commissioner View" to "Hiring".
     - Use one vocabulary throughout.
2. **[P1] No component primitives, so colour and status drift.**
   - About 700 raw palette classes, 7 category maps and 9 status maps, with "OPEN" and "Open" both in use.
   - Emerald competes with the brand green.
   - **Fix:**
     - Add semantic tokens for status and category.
     - Build `Button`, `Badge`, `StatusBadge`, `CategoryBadge`, `EmptyState` and `PageHeader`.
     - Keep one green.
     - Remove the design-literal exemptions as each file adopts these.
3. **[P1] Tables and cards don't adapt to phones.**
   - My Listings wraps the title one word per line.
   - Admin Users pushes its actions off-screen.
   - Feed cards truncate titles to fit a button.
   - **Fix:** tables become stacked rows below `md`, and on phones card calls-to-action sit under the text.
4. **[P1] Admin moderation is loud and unsafe.**
   - Three saturated buttons on every row, including on the admin account.
   - Warn needs no confirmation or reason.
   - The dialogs say "this user" instead of the name.
   - **Fix:** one "Moderate…" action opening a dialog with the user's name, a choice of action and a required reason. Admin rows and your own row get no actions.
5. **[P2] Error states look like success, and surfaces are decorative.**
   - Invalid inputs keep the green focus ring, and errors don't clear when the value is fixed.
   - Decorative gradients on the greeting, profile banners and Reports header.
   - Emoji section headings.
   - Text sizes of 9–11 px.
   - The profile name straddles the banner edge.
   - An always-red "Reports" nav item.
   - **Fix:**
     - An invalid-input style, and clear each error on change.
     - Flat brand surfaces.
     - Line icons instead of emoji.
     - A 12 px text floor.
     - Pull up only the avatar on profiles.
     - A neutral Reports item.

## Minor observations
- The poster's rating is missing from the commission page, which also says "1 commissions posted".
- The post form's native "Choose File" input clashes with every other control.
- Own-profile copy is in the third person ("give them a chance").
- The Messages header says "CSU Marketplace member" with no commission context.
- The Admin Listings status tiles that double as filters are a good pattern to reuse.

## Plan (Phase 4, refinement)
1. **Foundation:**
   - Self-hosted font via `next/font`.
   - Semantic colour tokens for status, category, danger, warning and info; one green.
   - A fixed type scale with a 12 px floor.
   - Invalid-input and `focus-visible` styles.
   - Themed selection, scrollbars and tabular numbers.
2. **Primitives:** `Button`, `Badge` / `StatusBadge` / `CategoryBadge`, `PageHeader`, `EmptyState`, `Skeleton`. Commission and status labels come from `lib/labels.ts`.
3. **Surfaces:** replace gradients with flat brand; line icons instead of emoji; fix the profile header; neutral Reports.
4. **Mobile:** stacked rows for tables; card calls-to-action under the text.
5. **Admin:** moderation dialog with a reason; page titles; readable log lines.
6. **Product-specific moment:** a lifecycle stepper on the commission page and hub cards.
7. **Vocabulary:** "commission" throughout, "Hiring" instead of "Commissioner View", roles shown only where they mean something.

Every screen then drops its `eslint-disable no-restricted-syntax` line. The lint rule makes this checkable.
