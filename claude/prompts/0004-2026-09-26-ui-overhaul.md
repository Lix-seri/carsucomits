# CarsuComits UI Overhaul: Master Prompt

## Role
You are a senior product designer and front-end engineer. Redesign the UI of CarsuComits so it feels fun, lively and trustworthy. Keep all business logic, routes, data models, auth and permissions exactly as they are. This is a visual and interaction overhaul, not a rewrite.

## Skills to use
- Use the **taste** skill to set a distinctive visual direction and avoid generic templated "AI SaaS" defaults.
- Use the **impeccable** skill for the full design pass. Audit and critique the current UI first, then apply fixes. Polish typography, color, spacing, motion, empty states and delight, then run a final audit before finishing.
- Read both skills before writing any code. Where they conflict, follow taste for aesthetic direction and impeccable for craft, accessibility and polish.

## What CarsuComits is
CarsuComits is the official, university-exclusive commission marketplace of Caraga State University – Main Campus (Ampayon, Butuan City). Students post tasks with a fare (₱) and a deadline, classmates apply, the poster hires one, reviews the delivery, and both sides rate each other.
- Categories: Academic (tutoring only, never doing graded work), Technical, General Errands, Administrative
- Skill levels: Beginner, Intermediate, Advanced, Expert
- Every account requires a @carsu.edu.ph email
- Roles: Student, USED officer, Admin
- Payments are NOT handled by the platform. "Completed" means the work is done, not that money changed hands.
- Core promise: safer than random Facebook posts. No scams, no ghosting, reputations are earned.

The UI should feel like a busy, friendly campus bulletin board: students helping students. Energetic and warm, but still trustworthy enough that people will hand over ₱ and their time.

## Problems with the current UI (fix all of these)
1. Visually flat. Almost everything is white, gray and one green. No illustration, no personality, no depth.
2. Big dead whitespace on the landing page. The hero has no visual anchor, and the 4-step card is a plain list.
3. Brand mark is just "CC" in a green square.
4. Browse cards: titles and descriptions truncate at 4 columns, cards look identical, and categories have no visual identity.
5. The dashboard "Hiring" card stepper is truncated ("P — H — D — Co…"). Redesign it so all four stages are readable.
6. Awkward copy: "Due No deadline", and "Earned on completed work, from" with an unfinished label. Rewrite all such microcopy.
7. Empty states ("Nothing in progress", "No active jobs", "No one is waiting", "No transactions yet") are gray boxes with a tiny icon. They should be inviting and point to a clear next action.
8. The profile page is sparse: empty skills box, no banner personality, weak stats.
9. The admin overview top stats are cut off and the whole panel lacks visual hierarchy.
10. Naming is inconsistent. The site says "CarsuComits". Confirm the final spelling with me before touching the logo or copy, and use it consistently everywhere (title tags, meta, emails, favicon).

## Brand and logo
Create an initial logo as a clean, scalable SVG:
- Concept ideas (pick the strongest or combine): a speech bubble plus a handshake or checkmark ("commission accepted"); a pushpin on a bulletin note (campus board); a stylized "C" that doubles as an arrow or cycle of posting, hiring, delivering and rating.
- Deliver: full wordmark, icon-only mark, favicon (16/32/180/512), a monochrome version, and a version that works on the dark admin sidebar.
- Keep it geometric and friendly. Rounded corners, bold weight, legible at 16px.
- Do NOT use the official CSU seal or any university logo. This is a student marketplace and must not imply it is an official seal. You may nod to campus identity through color only.

## Design system (build this first, as tokens)
**Color**
- Keep a green primary (it already reads as "campus" and "go"), but make it richer and pair it with a warm secondary like sunny gold or yellow, plus one playful accent (coral or tangerine) for highlights, badges and celebration moments.
- Give each category its own color and illustration:
  - Academic: blue or indigo, book or lightbulb
  - Technical: violet, laptop or code brackets
  - General Errands: orange, tricycle or shopping bag (local flavor)
  - Administrative: teal, clipboard or spreadsheet
- Give skill levels a visual scale (1 to 4 filled pips, bars or tiers) instead of plain text chips.
- Use a soft off-white or warm cream background, not sterile gray. Add subtle texture: faint dot grid, paper grain or blob shapes in the hero.
- Include a full dark mode that is checked for contrast.
- Meet WCAG AA contrast everywhere, including text on colored chips.

**Typography**
- Use a characterful display font for headings (e.g. Bricolage Grotesque, Space Grotesk or Cabinet Grotesk) and a clean, highly readable body font (e.g. Plus Jakarta Sans or Inter).
- Use a clear type scale with tight tracking on big headings. Peso amounts should be bold, tabular and prominent.

**Shape, depth and texture**
- Use generous rounding (12–20px on cards), soft layered shadows, and slight hover lift.
- Sticker-style badges for status ("Open", "New member", "Verified @carsu") with a slight tilt or outline.
- Use a consistent icon set (lucide is fine) with duotone or colored backgrounds for category icons.

## Illustrations and art
- Add original illustrations, as inline SVG or a lightweight illustration style, for: the hero, each of the 4 "how it works" steps, each category, every empty state, 404/error pages, and success moments.
- Optional: an original friendly mascot (for example a little courier or "Comi" character) that appears in empty states, onboarding, and the success screen. It must be fully original, not based on any existing character.
- Local flavor where natural: campus scenes, tricycles, a print shop, jeepney-style color accents, study tables. Keep it tasteful, not a tourism poster.

## Page-by-page direction

### Landing page
- Hero: bold headline with one highlighted word (underline scribble or marker highlight), a hero illustration or animated collage of floating example commission cards, and both CTAs.
- Live trust strip: counts such as open commissions, students joined, commissions completed (pulled from real data, animated count-up; hide if zero).
- "How it works": turn the 4 steps into an illustrated horizontal flow with connecting dashed paths that animate on scroll. Stack vertically on mobile.
- Category showcase: 4 colorful tiles with illustrations that link into Browse with that filter applied.
- "Why not just Facebook?" comparison section: scams, ghosting and no reputation vs. verified @carsu.edu.ph, ratings and one dashboard.
- Academic integrity callout, friendly but clear: "Tutoring yes, doing someone's graded work no."
- A fuller, more alive footer.

### Browse
- Sticky filter bar. Category chips show their color and icon. Skill chips show the level scale. Show active-filter pills with clear-all.
- Commission cards: category color strip or corner, illustration or icon, title (max 2 lines, no awkward mid-word truncation), fare as a bold ₱ badge, deadline as a human countdown ("Due in 3 days", "No deadline"), poster avatar and rating, applicant count, save/bookmark heart with a satisfying toggle animation.
- 3 columns on desktop so titles breathe. Skeleton loaders while fetching. Friendly empty result state with "clear filters" and "post one yourself".

### Dashboard home
- Personalized greeting with time-of-day illustration (morning, afternoon, evening).
- Redesign the hiring progress stepper: Posted, Hired, Delivered, Completed, fully labeled, with the current stage highlighted.
- "Your skills" nudge becomes an inviting prompt card with a progress ring ("Profile 40% complete").
- Suggested commissions based on the user's skills.

### My hub / Hiring / Messages / Saved
- Clear tabs and counts, colored status badges, a timeline view per job.
- Messages: modern chat bubbles, timestamps, typing/read states if the backend supports it (do not fake them).
- Every empty state gets an illustration, one warm line of copy and one action button.

### Profile
- Customizable banner (a few preset patterns or colors per user), avatar with ring, "Verified @carsu.edu.ph" badge.
- Skills as colorful tags with level pips. Stats as small cards. Reviews with star breakdown. Portfolio or finished-work gallery if data exists.
- Achievement badges, e.g. "First commission", "5 five-star reviews", "Fast responder". Only show badges the backend can actually compute.

### Transactions
- Keep the "CarsuComits doesn't handle payments" notice, but style it as a clear info banner.
- Fix the summary labels. Show earned vs. paid with a small chart when there's data.

### Admin panel
- Keep it calmer and more professional than the student side, but still branded.
- Fix the clipped overview stats. Use KPI cards with trend indicators, charts for signups and commissions over time, a moderation queue with severity colors, clear user status badges (Active, Warned, Suspended, Banned), and safe confirmation dialogs for destructive actions.
- Present the "Make USED officer" and "Moderate…" actions with consistent button hierarchy.

### Auth (sign in / create account)
- Split layout with illustration. Inline validation that explains the @carsu.edu.ph rule before submit. Friendly success screen after signup.

## Interactivity and motion
- Micro-interactions: button press scale, card hover lift and tilt, chip toggle bounce, bookmark heart pop, toast notifications with icons.
- Scroll-reveal for landing sections (subtle fade and rise, staggered).
- Celebration moments: confetti or a mascot animation when a commission is posted, someone is hired, work is approved, or a rating is submitted.
- Page transitions and skeleton loaders instead of blank flashes.
- Notification bell with an unread dot and a dropdown panel.
- Command-palette style global search (Ctrl/Cmd+K) if feasible with existing search endpoints.
- Respect `prefers-reduced-motion`: disable non-essential animation.
- Keep motion fast (150–300ms) and purposeful. Nothing should slow down getting work done.

## Microcopy
- Warm, student-to-student voice. Short and clear. A light touch of Taglish is fine in fun spots (empty states, success messages) but keep core instructions in clear English.
- Replace every awkward string noted above and review all buttons, labels and errors.

## Quality bar
- Fully responsive: test at 360px, 768px, 1024px and 1440px. The sidebar becomes a bottom nav or drawer on mobile.
- Keyboard accessible with visible focus states, correct ARIA on interactive components, alt text on illustrations (or `aria-hidden` when decorative).
- Performance: optimize SVGs, lazy-load heavy illustrations, no layout shift, keep Lighthouse performance and accessibility at 90+.
- No new heavy dependencies without justification. Prefer CSS and small libraries.

## Process
1. Read the taste and impeccable skills, then inspect the codebase and stack.
2. Run an audit of the current UI and list findings.
3. Propose the design direction (palette, fonts, logo concepts) and wait for my approval before implementing.
4. Build the design tokens and shared components first, then roll out page by page: landing, browse, dashboard, profile, remaining student pages, auth, admin.
5. After each page, run a critique and polish pass and fix what it finds.
6. Finish with a full audit, a before/after summary, and a list of anything you couldn't do because the backend doesn't support it.

## Hard constraints
- Do not change API contracts, database schema, auth, role permissions, or routing.
- Do not invent data or fake features. Hide any UI element whose data doesn't exist yet.
- Do not use copyrighted characters, the official CSU seal, or third-party logos.
